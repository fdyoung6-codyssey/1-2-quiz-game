# 성능 측정 (PERFORMANCE)

`python tools/benchmark.py`로 퀴즈 개수를 늘려 가며 실제로 측정한 결과입니다.

- 측정 일시: 2026-11-09 19:38
- 환경: Python 3.14.10 / Windows 11
- 각 시간은 5회 반복 평균, 메모리는 `tracemalloc`으로 잰 불러오기 시 최대 사용량
- 실제 state.json이 아닌 임시 폴더에서 측정

## 측정 결과

| 퀴즈 수 | 저장 (ms) | 불러오기 (ms) | 목록 출력 (ms) | 키워드 검색 (ms) | 파일 크기 (KB) | 메모리 최대 (MB) |
|---:|---:|---:|---:|---:|---:|---:|
| 100 | 1.0 | 0.3 | 0.0 | 0.00 | 34 | 0.27 |
| 1,000 | 4.9 | 1.9 | 0.2 | 0.02 | 344 | 1.61 |
| 10,000 | 43.6 | 16.3 | 2.9 | 0.20 | 3455 | 15.09 |

## 분석

- **1,000개 기준**: 저장 약 5ms, 불러오기 약 2ms, 메모리 약 1.6MB로 사용자가 기다림을 느끼지 않는 수준입니다.
- 저장·불러오기·목록·검색은 모두 퀴즈를 처음부터 끝까지 한 번씩 확인하는 방식(O(n))이라, 퀴즈 수가 10배 늘면 시간도 약 10배 늘어납니다.
- 검색은 리스트를 처음부터 훑는 선형 검색입니다. 수만 개 이상으로 커지면 딕셔너리 색인이나 SQLite 같은 데이터베이스를 고려할 수 있습니다.
- `save_data()`는 매번 파일 전체를 다시 씁니다. 퀴즈가 매우 많아지면 변경된 부분만 저장하는 방식이 필요하지만, 이 프로그램의 일반적인 사용량(수십~수백 개)에서는 충분합니다.

## 같이 확인한 것

- 각 크기마다 저장한 개수와 다시 불러온 개수가 같은지 `assert`로 확인했습니다.
- 자동 테스트(`python -m unittest discover -s tests -v`)에도 1,000개 저장·불러오기 테스트가 들어 있습니다.
